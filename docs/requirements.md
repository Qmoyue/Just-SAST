# Just 产品要求

产品契约：`JUST-LIGHT-MINING-V3`。

Just 是面向 Java 组件、应用和 CTF 制品的轻量级静态反序列化链分析工具。产品输出应帮助审计者回答：入口是什么、对象和控制条件如何连接、哪些依赖与 JDK 条件成立、最终影响在哪里，以及哪些事实仍然未知。

## 1. 输入与运行环境

- 主程序使用 JDK 17 运行，构建使用 Maven 3.6 或更高版本。
- 输入支持 JAR、WAR、Spring Boot fat JAR、嵌套归档和 class 目录。
- 输入可以包含显式依赖目录、依赖 JAR、Maven POM、本地缓存和目标 JDK。
- `--jdk-home` 指定目标字节码和运行库来源；Java 8 使用 `rt.jar`，Java 9 及以上使用 JRT/JDK 布局。目标 JDK 与 Just 主程序的 JDK 相互独立。
- 目标应用不需要启动。扫描器只读取制品和依赖，不运行目标构建插件或目标应用。

## 2. 分析模式

| 模式 | 分析对象 | 完整结果条件 |
| --- | --- | --- |
| `component` | 机制触发点到最终影响的 gadget 链 | 触发、对象、控制、依赖和终点条件可解释 |
| `application` | 真实应用入口到最终影响的应用链 | 入口、可控输入、站点、必要桥、对象/控制关系和完整终点均有证据 |

两种模式共享字节码事实、传播、约束、桥接和报告模型。组件链可以没有应用入口；组件链存在不代表应用暴露。类名共现、classpath 共存和调用图共现不能代替值流、对象身份或控制关系。

覆盖范围包括 Java 原生序列化及规则描述的框架入口、反射、代理、lambda、JNDI/RMI、JDBC/XML 和二次解析等常见语义。结果必须标明依赖、版本、配置、JDK 和输入完整性条件，不宣称未建模版本自动成立。

## 3. 依赖与制品身份

- 依赖优先来自输入内置字节码、显式参数和完整本地缓存，再根据明确的 POM 解析补齐。
- POM 解析处理父 POM、属性、BOM、`dependencyManagement`、传递依赖、scope、optional、exclusions、classifier、type 和 Maven 版本仲裁。
- `--repository` 只允许用户显式指定仓库；`--offline` 禁止元数据和归档的网络请求。
- 不根据类名猜测坐标、版本或替代制品，不运行 POM 中的插件、extensions 或目标类。
- 每个依赖记录坐标、具体版本、来源、SHA-256、引入关系和仲裁原因；嵌入、显式、缓存和远程来源可区分。
- 下载失败、缺少制品、版本不确定、依赖冲突和重复类会在结果中披露，并影响相应链的完整性。
- 缓存只接受完整制品和完整报告。缓存预检、恢复和写入错误直接失败，不静默降级。

## 4. 静态分析与安全边界

- ASM 负责读取字节码；后续层消费稳定、不可变的程序事实和制品 provenance。
- 分析器不加载、初始化、构造、反射调用或执行目标类，不反序列化攻击流，不启动目标进程，不访问目标危险终点。
- 不生成 payload、投递字节流或 `RCE_CONFIRMED` 结果。
- 入口、sink、callback、摘要和规则是数据；求解、约束、控制和组合是通用语义。
- 内部不变量错误直接失败。外部输入校验、资源预算和 UNKNOWN 在对应边界一次性处理，不吞异常、不猜值、不静默重试。

## 5. 有界静态筛选

筛选服务于高成本或高噪声位置，只计算 Just 支持的有限操作，例如常量字符串、算术、比较、分支和有限反射名称。输入包括已知值或保持关联的完整有限域、程序位置和局部预算；输出包括证明、条件或明确未知。

筛选状态定义如下：

| 状态 | 产品语义 |
| --- | --- |
| `PROVABLY_UNREACHABLE` | 存在完整局部矛盾证明，可以阻断对应路径 |
| `PROVEN_RETAINED` | 局部事实支持保留，不能单独证明完整链 |
| `UNKNOWN` | 事实或语义不足，候选保留 |
| `BUDGET_EXCEEDED` | 局部预算耗尽，候选保留并记录完整性影响 |

只有完整的 `PROVABLY_UNREACHABLE` 证明可以剪枝。一次成功求值、部分采样、未知域、预算耗尽或目标异常不能否定静态链。每个筛选点记录 kind、位置、原因、域摘要、预算、评估数、保留数和拒绝数，筛选状态进入统一报告。

## 6. 报告与接口

公开扫描接口为：

```text
scan --jar <jar|war|class-dir>
     [--mode component|application]
     [--deps <jar|dir,...>] [--pom <pom.xml>]
     [--repository <url>] [--offline]
     [--jdk-home <path>] [--output <path>] [--rules <path>]
```

高级工作流提供 `--stats`、`--fast`、`--baseline`、`--suppressions` 和 `--cache`。`--cache` 与 `--baseline`、`--suppressions` 互斥。所有参数的范围、默认值、错误和退出状态由 CLI help 与报告说明。

一次扫描生成同源的 `report.md`、`report.json`、`index.md`、`evidence/` 和 `meta/`。报告至少提供：

- 可解析的入口、站点、sink、最终影响和链身份；
- 每跳方法签名、字节码位置、字段/对象连接和控制依据；
- 依赖、JDK、制品 hash、配置、输入 digest 和来源；
- 完整性、应用暴露、结构可行性、控制状态和筛选状态；
- UNKNOWN、预算、截断、缺依赖、未解析端点和关键假设；
- dependency、network、analysis、report、total 分段耗时。

Markdown 是人工阅读入口，JSON 是机器消费入口；二者引用同一冻结快照。排名只表示展示顺序，不构成可达性或漏洞确认。

## 7. 质量基线

- 固定 CTF/WP 主链应逐案保留完整入口、桥、对象/控制条件和最终影响。
- Apache 组件与应用正负样本应按实际版本、部署条件和输入完整性验证。
- 低误报评估使用证据支持比例，UNKNOWN 计入分母；明确矛盾和伪完整结果必须为零。
- 真实性、准确性、资源消耗和审查负担同时评估；速度不能通过隐藏候选或降低语义强度获得。
- 行为测试覆盖两种模式、依赖补齐与离线、目标不执行、筛选状态、报告一致性和错误暴露。
- `tools/` 与 `benchmark/` 仅服务开发验证，不参与用户运行时和发布 launcher 的装配。
